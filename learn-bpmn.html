CHAPTER 01はじめに – BPMNで業務を見える化・改善する

1.1BPMNとは？ – 業務プロセスの共通言語

BPMN（Business Process Model and Notation）とは、業務プロセスを視覚的に記述するための国際標準の表記法です。複雑な業務の流れを、誰にでも理解しやすい図（BPMN図）として表現することができます。 組織内での多様な業務は、しばしば複数の部署や担当者が関わり合って遂行されます。BPMNは、これらの関係者間で業務プロセスに関する認識を統一し、誤解を防ぐための「共通言語」としての役割を果たします。

従来の文字ベースの業務マニュアルでは、全体の流れや関連性が把握しにくく、更新も煩雑になりがちでした。BPMNを用いることで、業務の開始から終了までの一連の流れ、各ステップでの作業内容、判断条件、担当者などを視覚的に明確にできます。

1.2なぜBPMNなのか？ – 利用時のメリットと目的

BPMNを導入することには、多くのメリットがあります。これらは組織の業務効率と透明性を大幅に向上させる可能性を秘めています。

  • 業務の可視化と理解促進：
    複雑な業務プロセスを誰にでも分かりやすく「見える化」することで、関係者間の共通理解を深めます。これにより、業務の全体像を把握しやすくなり、個々の作業がプロセス全体の中でどのような役割を担っているのかが明確になります。
  • 非効率性の発見と業務改善：
    プロセスを客観的に図示することで、これまで気づかなかったボトルネック、無駄な作業、重複作業などが明らかになり、具体的な改善策を検討するための土台となります。
  • 標準化と属人化の解消：
    業務手順を標準化することで、特定の担当者しか業務内容を詳細に把握していないといった「属人化」の状態を解消できます。
  • 職員研修・引継ぎの効率化：
    視覚的に分かりやすいBPMN図は、新人研修や人事異動時の業務引継ぎ資料としても非常に有効です。
  • システム調達・開発の効率化：
    情報システムの導入や更新の際に、BPMN図は業務要件を明確に伝えるための有効な手段となります。
  • 法令改正への迅速な対応：
    行政事務は法令に基づいて行われるため、法令改正は業務プロセスの変更を伴います。プロセスが可視化されていれば影響箇所を迅速に特定できます。

1.3本ハンドブックの読み進め方

本ハンドブックは、BPMNを初めて学ぶ方でも理解しやすいように、基本的な概念から具体的な作成方法、活用事例までを段階的に解説します。第2章で基礎知識、第3章でエディタの使い方、第4章で実例、第5〜6章で運用のコツを扱い、巻末の付録には図形の早見表と理解度チェックを収録しています。目次から気になる章に直接ジャンプしても構いません。

POINT 初めてBPMNに触れる方は、第2章2.1〜2.2 → 第3章 → 第4章の順に読むと、最短で「自分の業務を図にする」ところまでたどり着けます。

CHAPTER 02BPMN 2.0の基本

2.1基本的な考え方

BPMNには多くの図形やルールがありますが、最初からすべてを覚える必要はありません。まずは、業務プロセスを表現するための最も基本的な考え方と、主要な要素を理解することから始めましょう。

  1. 横長の四角形（プールとレーン）を書き、部署名や役割で区切る（誰が関わるか）。
  2. 角丸の四角形（タスク）を並べる（何を行うか）。
  3. 矢印（シーケンスフロー）でつなぐ（どのような順番で行うか）。
  4. 開始を細い円（開始イベント）、終了を太い円（終了イベント）で示す。

2.2主要な図形要素

BPMN 2.0でよく使われる主要な図形要素とその意味を解説します。

図形名称簡単な意味と利用例
開始イベントStart Event プロセスの開始点（細い線の円）。例：申請受付開始、定時処理開始。
終了イベントEnd Event プロセスの終了点（太い線の円）。例：処理完了、通知発行完了。
タスクTask 個別の作業単位（角が丸い四角形）。例：「申請書を確認する」「データを入力する」。
排他ゲートウェイExclusive Gateway 複数の経路のうち、条件に合致する「一つだけ」に進む。
並行ゲートウェイParallel Gateway 複数の経路を「同時に」実行、または全経路完了を待つ。
シーケンスフローSequence Flow 要素の実行順序、プロセスの流れ（実線の矢印）。
プール／レーンPool / Lane 参加者やプロセス全体の括り（プール）と、その中の役割・担当者（レーン）。例：「窓口担当」「承認者」。
メッセージフローMessage Flow 異なるプール間のメッセージや情報のやり取り（破線の矢印）。
データオブジェクトData Object プロセスで扱う情報や書類。例：「申請書」「報告書」。
関連Association 要素と注釈・データオブジェクトなどを結びつける点線。

これらの図形を組み合わせることで、業務プロセスを具体的に表現していきます。業務の可視化が進むことで、関係者全員が同じ理解を持つことができ、業務改善の議論がスムーズになります。

2.3BPMN記載レベル

BPMNにはいくつかのレベルがあり、目的に応じて使い分けられます。地方自治体においては、特に「分析レベル」での記述が推奨されることが多いようです。

  • 記述レベル：事務の基本的な作業の流れを記載するレベル。
  • 分析レベル：記述レベルの内容に加え、事務の詳細や例外的な処理までを表記するレベル。これが標準化や属人化の解消に繋がります。
  • 実行可能レベル：RPAの詳細設計資料やプログラム開発のための設計資料として詳細に記載するレベル。

「分析レベル」での記述ができると、業務が正確に把握可能となり、職員研修・引継ぎの効率化にも大いに役立ちます。

2.4イベントの種類を理解する

イベントは円で表現されますが、線の太さ・重なり・内側のアイコンによって「いつ・何によって」プロセスが動くのかを細かく表現できます。まずは3つの見分け方を覚えましょう。

見分け方の基本 ①線の太さ：細い線＝開始、二重の細い線＝中間、太い線＝終了。
②塗りつぶし：白抜き＝キャッチ（受動的に発生を待つ）、黒塗り＝スロー（能動的に発信する）。
③内側のアイコン：無印＝プロセスの開始・終了、封筒＝メッセージ、時計＝タイマー、稲妻＝エラー。
図形名称意味と利用例
開始イベント（無印）None Start Event 特にトリガーを指定しない、標準的なプロセスの開始点。
メッセージ開始イベントMessage Start Event 他者からのメッセージ（申請書の到着など）でプロセスが開始する。
タイマー開始イベントTimer Start Event 特定の日時・周期でプロセスが開始する。例：毎月1日の定例処理。
中間イベント（メッセージ受信）Intermediate Catch (Message) プロセスの途中で、他者からのメッセージ（回答・承認結果など）を待って先に進む。
中間イベント（タイマー）Intermediate Catch (Timer) 一定時間の経過や特定の日時まで処理を待機させる。例：「3営業日後」。
終了イベント（無印）None End Event 特に結果を指定しない、標準的なプロセスの終了点。
メッセージ終了イベントMessage End Event プロセスの終了とともに、他者へメッセージ（通知）を送信する。
エラー終了イベントError End Event 異常な状態でプロセスを終了し、エラーを発生させる。
終了（強制終了）イベントTerminate End Event プロセス内の他の全ての進行中の活動も含めて、直ちに終了させる。

実務でよく使うのは「メッセージ」と「タイマー」の2種類です。「誰かからの連絡待ち」はメッセージイベント、「一定期間・特定日時の経過待ち」はタイマーイベント、と覚えておくと使い分けに迷いません。

2.5サブプロセスと境界イベント

業務が複雑になり1つのタスクでは表現しきれない場合や、複数の手順をひとまとまりとして扱いたい場合には「サブプロセス」を使います。また、タスクの実行中に割り込みで発生しうる例外（急な問い合わせ、期限切れなど）は「境界イベント」で表現します。

サブプロセス（Sub-Process）

タスクの角丸四角形の下部中央に「＋」マークが付いた図形で、複数のステップから成る詳細な処理をひとまとめに折りたたんで表現します。本エディタでは、この＋マークをクリックすると詳細フロー（内部の図）を展開・編集できます。

申請書を 受け付ける
⟶
審査を 行う（詳細）
⟶
結果を 通知する
図2.5a　サブプロセス（＋マーク）は、クリックすると内部の詳細フローが展開される

境界イベント（Boundary Event）

タスクやサブプロセスの外枠上に配置される、二重丸の小さいイベントです。そのタスクの実行中に特定の事象（メッセージの割り込み、タイムアウト、エラーなど）が発生した場合の「例外ルート」を表現します。

図形名称意味と利用例
境界タイマーイベントBoundary Timer Event（中断） 一定時間内に処理が終わらない場合、タスクを中断して例外ルートへ分岐する。例：「3日以内に返信がなければ督促」。
境界タイマーイベント（非中断・破線）Boundary Timer（非中断） 元のタスクは中断せず継続したまま、並行して別ルートを開始する。例：処理を続けつつ一定時間後にリマインド通知を送る。
境界メッセージイベントBoundary Message Event タスク実行中に外部からのメッセージ（取消依頼など）を受けて中断・分岐する。
境界エラーイベントBoundary Error Event タスク内でエラーが発生した場合に、専用のエラー処理ルートへ分岐する。
注意 境界イベントの外枠が実線の二重丸なら「中断（Interrupting）」＝元のタスクは止まります。破線の二重丸なら「非中断（Non-interrupting）」＝元のタスクは動いたまま並行して例外処理が始まります。この違いを取り違えると、図の意味が正反対になるので注意しましょう。

CHAPTER 03BPMNエディタ入門

BPMN図を作成するためには、専用のエディタを利用すると便利です。ここでは、本サイトのBPMN作図ツール（bpmn.jsベース）を例に、基本的な使い方を解説します。

3.1画面構成と基本機能

BPMNエディタは、以下のような共通の画面構成と機能を備えています。

  • キャンバスエリア：BPMN図を実際に描画し、編集する中心的な作業領域。画面全体に大きく確保されています。
  • パレット：BPMNの各要素（イベント・タスク・ゲートウェイなど）がアイコンとして並んでいる領域。キャンバス左側に表示されます。
  • プロパティパネル：選択した要素の詳細情報（名称、担当者、実行条件など）を設定・編集する領域。要素を選択すると右側に表示されます。
  • コンテキストパッド：要素を選択した際にその周囲に現れる、よく使う操作（接続・削除・変形など）のショートカットメニュー。
  • フローティングツールバー：画面右下に常駐する、ファイル操作用のアイコン群。詳細は次項で解説します。

3.4初めてのBPMN図作成（要素の配置、接続、ラベル付け）

簡単なBPMN図を作成する基本的な手順は以下の通りです。

  1. プールの配置：パレットから「プール」を選択し、キャンバスに配置します。
  2. 開始イベントの配置：プールの左端の適切なレーンに「開始イベント」を配置します。
  3. タスクの配置：具体的な作業を表す「タスク」をパレットから選択し配置します。
  4. シーケンスフローでの接続：配置した要素をコンテキストパッドの矢印アイコンから「シーケンスフロー」でつなぎます。
  5. ゲートウェイの配置と分岐：条件分岐がある場合は、「ゲートウェイ」を配置します。
  6. 終了イベントの配置：プロセスの右端に「終了イベント」を配置します。
  7. ラベル付け：要素を選択して E キー（またはダブルクリック）で、内容が明確にわかる名称を付けます。これが業務の可視化と理解促進の鍵です。
  8. 保存： Ctrl+S または保存ボタンで、作成したBPMN図をBPMN形式（XML）で保存します。

最初は簡単なプロセスから始め、徐々に慣れていくことが大切です。

このように、直列に並べるだけでなく並行ゲートウェイを使うことで、実際の業務にある「同時進行」の様子も正確に表現できます。また境界イベントを加えることで、期限超過などの例外対応まで含めた実務に近い図になります。

CHAPTER 05分かりやすいBPMN図作成のためのヒント集

5.1初心者が陥りがちなワナと、その回避策

  • ワナ1：複雑すぎる図 → 回避策：基本要素から始め、できる限り1ページに収めるようにしましょう。収まらない場合はサブプロセスで折りたたむことを検討します。
  • ワナ2：フローの方向がバラバラ → 回避策：左から右への流れで記載するルールを守りましょう。
  • ワナ3：ゲートウェイによる混乱 → 回避策：分岐条件やシーケンスはわかりやすく記述しましょう。条件分岐が続く場合には合流するゲートウェイを配置すると流れが明確になります。
  • ワナ4：プールとレーンが曖昧 → 回避策：「誰が」行うかを意識し設定しましょう。
  • ワナ5：曖昧さ・命名規則の不統一 → 回避策：「目的語＋動詞」でわかりやすく、処理や手順書のIDを補足するとより明確になります。
  • ワナ6：境界イベントの中断／非中断の取り違え → 回避策：実線の二重丸は「中断」、破線の二重丸は「非中断」であることを都度確認しましょう。

これらのワナを避けることで、BPMN図の可読性が向上し、業務の可視化の効果が高まります。

5.2一目で伝わる図のルール

  • レイアウトの工夫：1ページに収める、フローの方向を統一、適切な間隔と整列。
  • 命名規則の徹底：タスク名は「（目的語）を（動詞）する」、イベント名も具体的に。
  • シンプル化の追求：使用する記号の種類を絞る、サブプロセスの利用、注釈の活用。

CHAPTER 06組織内でのBPMN活用

6.1BPMNを組織内で活用するためのステップ

  1. 目的の共有とリーダーシップ：なぜBPMNを利用するのか目的を明確にし、経営層・管理職がコミットする。
  2. スモールスタートと成功体験の共有：単純業務、身近な業務から試行し、成功事例を共有する。
  3. 支援体制の整備：記載方法についてのサポートや、ベテラン職員の業務知識を活かした支援体制を整える。
  4. 研修と学習機会の提供：研修を実施し、理解とスキルアップを支援する。
  5. ツール環境の整備：アクセスしやすく使いやすいBPMNエディタ環境を提供する。
  6. BPMN図の共有と日常的な活用：作成した図を共有し、業務マニュアルや改善検討資料として日常的に活用する文化を醸成する。
  7. 評価とフィードバックによる継続的改善：導入効果を定期的に評価し、改善サイクルを確立する。

これらのステップを通じて、BPMNは組織内の業務改善と標準化を推進する強力なツールとなります。

6.2研修の進め方と学習リソース

効果的な研修と学習リソースの提供は、BPMNスキルを組織全体に広める鍵です。

  • 研修計画：対象者と記載レベルに応じたプログラムを設計する。
  • 研修内容：BPMNの基本、エディタ操作、演習、分かりやすい図の作成ポイント、成功事例紹介など。
  • 演習の活用：本ハンドブック巻末の「理解度チェック」（付録D）を研修の理解度確認に活用できます。

これにより、職員がBPMNを効果的に活用できるようになり、職員研修や引継ぎの効率化が図られ、組織全体の業務改善能力が向上します。

CHAPTER 07おわりに

本ハンドブックを通じて、BPMNの基本的な知識と活用方法を学んでいただけたことと思います。

BPMNを習得し活用することで、以下のメリットが期待できます。

  • 業務の可視化：複雑なプロセスも一目で理解。
  • 業務改善：ボトルネックや無駄を発見し、効率化。
  • 標準化と属人化の解消：誰でも同じ品質で業務を遂行。
  • 職員研修・引継ぎの効率化：スムーズな知識移転。

BPMNのスキルは、個々の職員の能力向上だけでなく、組織全体の生産性向上とサービス品質の向上に大きく貢献します。まずは巻末の付録を参考に、身近な業務を1つ図にしてみましょう。

APPENDIX付録：図形の早見表・演習・用語集

Aタスクの種類

タスクは角丸の四角形で表現します。タスクの種類はタスク内の左上に表示されるマーカーの種類で見分けることができます。手作業タスク、何かのルールに基づくタスク、別に定義済のタスクなどを表現することができます。

図形名称意味と利用例
抽象タスクAbstract Task 汎用的なタスクです。特定のマーカーを持ちません。
手作業タスクManual Task システムを使用せずに人間が行う作業を表します。
ユーザタスクUser Task 人間が行う作業（システム使用を含む）を表します。
サービスタスクService Task システムやアプリケーションが実行する処理を表します。
スクリプトタスクScript Task プログラムやスクリプトを実行するタスクを表します。
ビジネスルールタスクBusiness Rule Task ビジネスルールエンジンを使用して判断や計算を行うタスクを表します。
サブプロセスSub-Process 複数の手順をひとまとまりに折りたたんで表現します。＋マークで展開できます（2.5節参照）。

Bゲートウェイの種類

ゲートウェイを適切に記載することはBPMNの利用において非常に重要です。

図形名称意味と利用例
排他ゲートウェイExclusive Gateway 条件に基づいて唯一の経路を選択します。最も基本的なゲートウェイです。
並行ゲートウェイParallel Gateway 複数の経路を同時に実行し、終了は同期します。
包含ゲートウェイInclusive Gateway 条件に基づいて1つ以上の経路を選択します。
イベントベースゲートウェイEvent-Based Gateway 発生したイベントに基づいて経路を選択します。
複合ゲートウェイComplex Gateway 複雑な条件に基づいて経路を制御します。

Cイベントの種類一覧

第2.4節・2.5節で解説したイベントを、開始・中間・境界・終了の4カテゴリで一覧にまとめました。

図形名称意味と利用例
開始イベントNone Start トリガー指定のない標準的な開始点。
メッセージ開始Message Start 他者からのメッセージでプロセスが開始する。
タイマー開始Timer Start 特定の日時・周期でプロセスが開始する。
条件開始Conditional Start 特定の条件が真になった時点でプロセスが開始する。
中間イベント（無印）None Intermediate 特に条件を指定しない中間の目印。
中間メッセージ受信Intermediate Message 途中で他者からのメッセージを待って先に進む。
中間タイマーIntermediate Timer 一定時間・特定日時まで処理を待機させる。
境界メッセージBoundary Message タスク実行中のメッセージ割り込みで例外ルートへ分岐。
境界タイマー（中断）Boundary Timer（中断） 期限超過でタスクを中断し例外ルートへ分岐。
境界タイマー（非中断）Boundary Timer（非中断） 元のタスクを継続しつつ並行して例外ルートを開始。
境界エラーBoundary Error タスク内のエラー発生時に専用の処理ルートへ分岐。
終了イベントNone End 結果を指定しない標準的な終了点。
メッセージ終了Message End 終了とともに他者へメッセージを送信する。
エラー終了Error End 異常な状態でプロセスを終了させる。
強制終了Terminate End 進行中の全活動を含め直ちにプロセスを終了させる。

Q2. 「誰かからの連絡（回答）を待って処理を進める」場合に使うイベントはどれですか？
Aタイマーイベント
Bメッセージイベント
Cエラーイベント
D終了（強制終了）イベント

Q3. 境界イベントの外枠が「破線の二重丸」の場合、元のタスクはどうなりますか？
A直ちに中断される
B中断せず、並行して例外ルートが開始する
C自動的に削除される
D無視される（意味を持たない）
破線の二重丸は「非中断（Non-interrupting）」を表し、元のタスクは動いたまま並行して例外ルートが開始します。実線なら「中断」で元のタスクは止まります。

A排他ゲートウェイ
B包含ゲートウェイ
C並行ゲートウェイ
Dイベントベースゲートウェイ
並行ゲートウェイ（Parallel Gateway、＋マーク）は複数経路の同時実行と、その後の同期（全経路の完了待ち）を表現します。

Bサブプロセス

E用語集

BPMN
Business Process Model and Notation。業務プロセスを視覚的に記述するための国際標準の表記法。
プール（Pool）
業務プロセス全体、または1つの組織・参加者を表す大きな枠。
レーン（Lane）
プール内を役割や担当者ごとに分割する区画。
シーケンスフロー
要素の実行順序を表す実線の矢印。同一プール内でのみ使用する。
メッセージフロー
異なるプール間でのメッセージ・情報のやり取りを表す破線の矢印。
ゲートウェイ
プロセスの分岐・合流を制御する菱形の図形。排他・並行・包含・イベントベース・複合の5種類がある。
境界イベント
タスクやサブプロセスの外枠上に配置され、実行中に発生しうる例外（メッセージ・タイマー・エラーなど）を表現するイベント。
サブプロセス
複数の手順をひとまとまりに折りたたんで表現する図形。詳細な内部フローを持つ。
キャッチ／スロー
キャッチは「イベントの発生を受け取る（待つ）」、スローは「イベントを発生させる（送る）」動作。
分析レベル
事務の詳細や例外処理まで記載するBPMNの記載レベル。標準化・属人化解消に有効。
属人化
特定の担当者しか業務内容を詳細に把握していない状態。標準化により解消が期待される。

2011年にOMG（Object Management Group）によって標準化されたBPMNの最新版仕様。
